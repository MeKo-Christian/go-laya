# Decisions

> The architectural decisions behind go-laya, each with the evidence that settled it. The ids are
> stable, and code, scripts and `PLAN.md` cite them (for example `D9`). A new decision gets the
> next free id. A reversed decision stays in place with a note saying what replaced it.
> Technical facts about the system are in [`ARCHITECTURE.md`](ARCHITECTURE.md). Open work is in
> [`../PLAN.md`](../PLAN.md).

## Core decisions

| #   | Decision                                                                                  | Rationale                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| --- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| D1  | **ONNX first, pure-Go native backend later**, both behind a `Backend` interface           | `DecisionModel.forward` is one static graph with no KV cache, no loop and no control flow. It exports to a single ONNX file, so there is exactly one numerics-parity surface. Reimplementing ModernBERT (RoPE, alternating local/global attention, GeGLU) up front would be weeks of work before anything ran.                                                                                                                                                                                                                 |
| D2  | **Pure-Go tokenizer, no CGO**                                                             | User decision. The build stays CGO-free and cross-compilable. The tokenizer is the largest correctness risk (R1), so the golden corpus came before the implementation. The promise holds end to end: `CGO_ENABLED=0 go build ./...` passes with the ONNX backend included (D5).                                                                                                                                                                                                                                                |
| D3  | **Inference only**                                                                        | `proper_reward` and `td_lambda_targets` are RLCD training math and are not ported. `collate_items` **is** ported (`internal/prompt.Collate`): `agent.py:266` calls it on every `system_one`, and its padding is what the graph sees. Dropped exports are listed in the README (PLAN Task 7.6.3).                                                                                                                                                                                                                               |
| D4  | **Upstream Python frozen under `original/`**                                              | It is the parity reference and drives `scripts/dump_python_parity.py`. It is committed rather than gitignored, because the Apache-2.0 attribution rests on it being visible. It is never edited.                                                                                                                                                                                                                                                                                                                               |
| D5  | **`shota3506/onnxruntime-purego`, pinned to `8db8bd7`; every `*Value` closed explicitly** | This binding keeps the build CGO-free and agreed with Python ORT to 3.8e-06. The `runtime.AddCleanup` panic `go-pocket-tts` hit is fixed at this pin. What remains is a data race: the binding has no synchronisation, and `Runtime.Close` (`runtime.go:178`) races the GC cleanup in `releaseValuePtr` (`value.go:152`). Closing every value explicitly takes the finalizer out of play, so it is a rule. Costs: an untagged pseudo-version of a 31-star repo. `yalue/onnxruntime_go` (cgo) is the fallback behind D1's seam. |
| D6  | **CPU is a batch deployment; no quantization by default; threads = physical cores**       | Spike S3 measured 0.6–1.9 s per question at 512 tokens on a 15 W laptop. Batching does not amortise on CPU (the per-question cost stays flat), and using all hardware threads loses 12–26 % against 8. A GPU execution provider is the answer for interactive use. int8 stays off until PLAN Task B.5 measures ECE and Brier (R4).                                                                                                                                                                                             |
| D7  | **Reference environment on transformers 5.17.0; 4.x is unsafe**                           | transformers 4.57.6 mis-parses mmBERT's `rope_parameters.sliding_attention.rope_theta` (160000) and uses 10000, which moves logits by 6.96. Fixing that one value makes 4.57.6 bit-identical, so this is a parsing bug. The ModernBERT-large checkpoints are identical across the major. Upstream's `transformers>=4.45.0` floor predates ModernBERT (4.48) and admits the broken versions. Checked with `scripts/crosscheck_transformers.py`.                                                                                 |
| D8  | **M8 is a zero-shared-library backend, not a speed play**                                 | ORT-CPU is bandwidth-bound, and a pure-Go forward pass is estimated at ~12 s against ORT's 1.7 s. What a native backend buys is a binary with no `.so` to acquire, pin or `dlopen`, which solves runtime pinning, Windows and wasm by construction. It comes after 1.0 and sits behind the same interface.                                                                                                                                                                                                                     |
| D9  | **`backend` is a public leaf package**                                                    | The binding swap (D5) is only real for users if `Backend` and `Batch` are importable. `backend/` has no dependencies, and `internal/backend/onnx/` holds ORT. Under purego nothing links ORT, so the checkable claim is that `go list -deps ./lang ./mailtext ./presets ./backend` names no purego (`TestNoMLDependency`). The root package may depend on the binding.                                                                                                                                                         |
| D10 | **Purpose-built pure-Go tokenizer; no vendored fork**                                     | `gomlx/go-huggingface` gets exactly laya's stages wrong (added-token semantics, Metaspace prepend, byte fallback), and gets right only the easy ~250 lines. `sugarme/tokenizer` lacks `byte_fallback`/`fuse_unk`. Result: two pipelines in ~750 lines, every semantic pinned by corpus before code. gomlx is a reference to read. `daulet/tokenizers` is R1's CGO fallback.                                                                                                                                                    |
| D11 | **Question types live in a leaf `question/`, re-exported at the root**                    | `presets` imports the types, and D9 requires `presets` to stay free of the binding. The root may depend on the binding, so root-resident types would have broken the check the moment M6 landed. The root holds type aliases only, and the public API is unchanged.                                                                                                                                                                                                                                                            |
| D12 | **`jsonx.Marshal` is the outer encoder wherever Python parity matters**                   | `encoding/json` runs `compact()` over whatever a `MarshalJSON` returns. Passing a `jsonx.Obj` through `json.Marshal`, directly or embedded, therefore strips `", "`/`": "` again. Every parity emitter (`Answer`, `Probs`, `RouteDecision`, the `routing` block) goes through `jsonx.Marshal`. Pinned by `TestEncodingJSONCompactsMarshalerOutput`.                                                                                                                                                                            |
| D13 | **The Router caches an `Agent` interface, widened in M7**                                 | All the Router asks of an agent is release: it caches, evicts and closes. So `Agent` is an interface with `Close() error`, and M7 widens it with `SystemOne`. Upstream's LRU tests use a bare stub object, and an interface plus `WithLoader` keeps them portable. Widening breaks third-party implementors, which is acceptable before 1.0.                                                                                                                                                                                   |

## Later decisions

These were made while doing a task. The task id is where the evidence was recorded, and the full
text is in the git history of `PLAN.md`.

| #   | Decision                                                                                                                | Rationale                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| --- | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D14 | **No cost-biased routing option** (Task 3.4.1)                                                                          | `laya-multilingual` is 2.2–3.2× faster, but upstream routes by language, and parity forbids changing the default. `ForModel("multilingual")` already expresses the request, so the Router's GoDoc cites the measured milliseconds instead of adding an option.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| D15 | **Invalid UTF-8 is sanitised at the API edge** (Tasks 4.1.2, 4.4.11)                                                    | `Encode` first applies `strings.ToValidUTF8(text, "�")`. A lone surrogate cannot round-trip through JSON (Python writes `\ud800`, Go decodes U+FFFD), so it has no fixture, and the boundary is tested Go-side. Without sanitising, bytes 0xF5–0xFF would be silently dropped on English (`unk:null`).                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| D16 | **The Router closes only agents its own loader built** (Task 3.2.4)                                                     | Python lets refcounting free an evicted agent, which in Go frees nothing, so eviction must `Close`. An attached agent is only forgotten: closing it would double-free an agent shared by two routers. `Unload` returns an error, because freeing can fail.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| D17 | **Default revision pinned to `1c5edc17a7acd8701df6fc341c0d179f1c62c982`** (Task 6.2.8)                                  | The Hub's `main` moved past the revision every golden vector describes. Following `main` is an explicit opt-in. A README deviation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| D18 | **The English checkpoint downloads only the repo root** (Task 6.2.9)                                                    | Upstream passes no `allow_patterns` for the root checkpoint and downloads all 2.4 GB. go-laya fetches only the root files (~846 MB). A README deviation. `Snapshot`'s `*` crosses `/`, so the loader needs a root-only filter. **Superseded by D24**, which downloads no weights at all.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| D19 | **The shipped export stays `eager`** (Task 6.5.2, user decision)                                                        | The `sdpa` export works under dynamo but matches the reference no better: at opset 18 both lower attention to the same `MatMul`/`Softmax`. It was worse on two checkpoints and better on one, all within ~1e-05 scaled.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| D20 | **ORT is a verified download; any 1.x from 1.23 is accepted** (Tasks 6.6.1, 6.6.2, user decision)                       | `internal/ortlib` pins ORT 1.23.0 archives by sha256 (linux/darwin × amd64/arm64), and `cmd/laya-ort` fetches them. `LAYA_ORT_LIB` still brings your own. `Open` reads `GetVersionString` before loading and rejects anything that is not `1.M.P` with M ≥ 23 (`ErrRuntimeVersion`). A newer 1.x would otherwise load silently.                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| D21 | **ONNX backend on a positive platform list; a stub elsewhere** (Task 6.7.2, user decision)                              | The backend builds on darwin/linux/netbsd on amd64/arm64, plus linux/loong64: the targets where purego builds cgo-free. Everywhere else `Open` returns `ErrUnsupportedPlatform`. Windows has not been tried (PLAN Task B.4).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| D22 | **`cuda` falls back to CPU with one warning** (Task 6.3.2, user decision)                                               | ORT's generic `SessionOptionsAppendExecutionProvider`, the only one the binding calls, rejects CUDA. Enabling it needs a binding change that moves D5's pin (PLAN Task B.3).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| D23 | **Parity emitters reject rather than guess on unordered input**                                                         | `jsonx` refuses a Go `map` (`ErrUnorderedMap`) instead of sorting it, and the fake backend refuses an unknown batch (`ErrUnknownBatch`) instead of returning zeros. A plausible wrong answer is the failure this port exists to prevent.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| D24 | **The forward pass is a local ONNX export; the loader downloads only config and tokenizer** (Task 7.2.1, user decision) | The Hub checkpoints ship safetensors, which only torch runs, and no ModernBERT-large ONNX is published. The default loader therefore reads `laya-<name>.onnx` from `WithONNXDir`, `$LAYA_ONNX_DIR` or `onnx/` under the laya cache: the file `scripts/export_onnx.py --out` writes. A missing export is `ErrNoGraph`, naming the command. A snapshot fetches `rl_agent_config.json` and `tokenizer/*` only, so no 0.8–1.7 GB of weights nobody reads. That the export matches the snapshot's revision cannot be checked from the graph, and is the exporter's responsibility.                                                                                                                                                                                        |
| D25 | **`state` stays `any`; no `State` interface** (Task 7.3.13, user decision)                                              | Python takes `str \| dict \| list`, and `lang.Analyse`, `lang.IsEnglish`, `Route` and `SystemOne` all take `any`. A `State` interface (`TextState`/`ObjState`/`ListState`, as `docs/API.md` once proposed) would narrow every call site for no parity gain: order-carrying values are already `jsonx.Obj`/`[]any`, and the prompt path refuses a Go `map` or struct loudly (D23, `ErrUnorderedMap`). Detection is more lenient (it reads a map's sorted keys) because it only picks a model; the prompt bytes are what must not be guessed.                                                                                                                                                                                                                          |
| D26 | **`act_probability` uses a port of ATen's softmax, not numpy's** (Task 7.3.10, user decision)                           | agent.py:295 runs the act head through `torch.softmax`. Measured on 4529 torch rows, numpy's `exp32` misses 96 `act_probability` values after `Round4`, all within 3 ulp of a tie; libm's exp misses 42. The user chose a port over accepting the gap: `calib.ActSoftmax` (SLEEF `xexpf`, multiply by `1/sum`) is bit-exact on all 4529. It covers any head width (verified on widths 1–20, 32 and 33, 8757 rows). The Go output is the same on every host; the reference is torch's AVX2 kernel, and the generator refuses any other. AVX512, NEON/SVE and the scalar kernel reduce in another order and are not verified.                                                                                                                                          |
| D27 | **`Predict` leases its agent; a dropped agent is closed after its last lease** (Task 7.7.6, user decision)              | Python keeps an evicted agent alive for a `predict` still holding it, because eviction only pops two dicts (router.py:188-195) and the local reference survives. Go closes on eviction (Tasks 3.2.4-3.2.6), so without a lease a concurrent request in another language at `max_loaded=1` closed the agent under a running pass, which Codex flagged as P1 on PR #30 against the Router's concurrency guarantee. Eviction, `Unload` and `Close` now drop at once, and the call that dropped the agent waits outside the lock for the passes on it, then closes it and reports the error as before. Rejected: the last release closes (a close error would have no caller), and documenting the failure (a deviation from Python). `Load` stays unleased and says so. |
